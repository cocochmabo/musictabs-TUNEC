# MusicTabs: от нуля до Google Play. Полное руководство для новичка

Это пошаговая инструкция без предположения, что ты уже что-то умеешь.
Иди по разделам строго по порядку — каждый следующий зависит от
предыдущего.

**Сколько это займёт**: реалистично — 2-4 недели, если делать не спеша
по вечерам. Не потому что сложно кодить (код уже написан), а потому что
Google Play проверяет новые аккаунты через обязательное закрытое
тестирование (14 дней, см. Шаг 9).

**Сколько это будет стоить**:
| Что | Стоимость |
|---|---|
| Регистрация аккаунта Google Play Console | $25 (один раз, навсегда) |
| Хостинг backend (Render.com, минимальный план) | ~$7/месяц (есть бесплатный, но он "засыпает") |
| AdMob, домен для privacy policy | Бесплатно (можно на GitHub Pages) |

---

## Шаг 0. Что вообще есть в проекте

Ты получил архив с двумя частями:
- `backend/` — сервер на Python, который анализирует треки (нужно
  задеплоить на хостинг, чтобы приложение могло к нему обращаться);
- `android-app/` — сам Android-проект (открывается в Android Studio).

Без задеплоенного backend приложение соберётся и запустится, но кнопка
"Загрузить трек" будет выдавать ошибку соединения — это нормально,
почини это в Шаге 4.

## Шаг 1. Установи инструменты

### 1.1 Android Studio
1. Зайди на https://developer.android.com/studio
2. Скачай версию для своей ОС (Windows/Mac/Linux), запусти установщик,
   везде жми "Next" со значениями по умолчанию.
3. При первом запуске Android Studio предложит скачать Android SDK —
   соглашайся, это займёт 10-20 минут.

JDK отдельно ставить не нужно — Android Studio идёт со встроенным.

### 1.2 Git (для загрузки backend на хостинг)
- Windows: скачай с https://git-scm.com/download/win, установи с
  настройками по умолчанию.
- Mac: открой Терминал, введи `git --version` — если не установлен,
  система сама предложит поставить.

### 1.3 Аккаунт GitHub
Зайди на https://github.com и зарегистрируйся (бесплатно). Он нужен,
чтобы отдать код backend хостингу.

## Шаг 2. Открой Android-проект

1. Распакуй архив, который тебе прислали.
2. Открой Android Studio → "Open" → выбери папку `android-app` (именно
   её, не весь архив целиком).
3. Внизу справа появится полоса "Gradle sync in progress" — подожди,
   первый раз может занять 5-15 минут (скачиваются зависимости).
4. Если Gradle ругается на версии (`Unsupported Gradle version` или
   похожее) — Android Studio сама предложит кнопку "Upgrade" или
   "Use suggested version", жми её.
5. Когда синхронизация закончилась без красных ошибок — вверху справа
   нажми зелёный треугольник ▶ ("Run"), выбери эмулятор (или подключи
   свой телефон по USB с включённой "Отладкой по USB" в настройках
   разработчика) — приложение должно запуститься.

Если приложение запустилось и открылся экран "Тюнер" — всё в порядке,
двигайся дальше.

## Шаг 4. Задеплой backend (сервер анализа аккордов)

Без этого шага фича "Табы" работать не будет.

### 4.1 Залей backend на GitHub
```bash
cd backend
git init
git add .
git commit -m "Initial backend"
```
Дальше на github.com нажми "New repository", назови `musictabs-backend`,
не добавляй README (у тебя уже есть файлы). Скопируй команды, которые
GitHub покажет после создания репозитория (что-то вроде):
```bash
git remote add origin https://github.com/ТВОЙ_НИК/musictabs-backend.git
git branch -M main
git push -u origin main
```

### 4.2 Задеплой на Render.com
1. Зайди на https://render.com, зарегистрируйся (можно через GitHub).
2. "New +" → "Web Service".
3. Подключи свой репозиторий `musictabs-backend`.
4. Render сам увидит `Dockerfile` и предложит "Environment: Docker" —
   соглашайся, отдельно ничего настраивать не нужно.
5. Выбери план (Free подойдёт для теста, но "засыпает" после 15 минут
   бездействия и первый запрос после сна будет долгим — для реального
   запуска бери Starter, ~$7/мес).
6. Нажми "Create Web Service", подожди 5-10 минут первого деплоя.
7. Когда деплой закончится, Render покажет адрес вида
   `https://musictabs-backend.onrender.com` — это твой `BACKEND_BASE_URL`.

### 4.3 Проверь, что backend отвечает
Открой в браузере `https://musictabs-backend.onrender.com/health` —
должно показать `{"ok":true}`.

### 4.4 Подставь адрес в приложение
В Android Studio открой файл:
`app/src/main/java/com/musictabs/app/MainActivity.kt`

Найди строку:
```kotlin
private const val BACKEND_BASE_URL = "https://your-backend.example.com/"
```
Замени на свой реальный адрес (обязательно со слэшем `/` в конце):
```kotlin
private const val BACKEND_BASE_URL = "https://musictabs-backend.onrender.com/"
```

## Шаг 5. Сделай иконку приложения

1. В Android Studio: правый клик на папке `app` → New → Image Asset.
2. В поле "Path" загрузи своё изображение (квадратное, минимум 512×512 px).
   Если нет готового изображения — можно быстро сделать в Canva
   (canva.com, бесплатно, шаблон "App Icon").
3. Нажми Next → Finish. Android Studio сама сгенерирует все нужные
   размеры иконки под разные экраны.

Также подготовь **отдельно** (понадобится в Шаге 11 для Play Console):
- Иконка 512×512 px, PNG, без прозрачности
- Feature graphic 1024×500 px (баннер для страницы приложения)
- 2-8 скриншотов самого приложения (сделай через эмулятор: на скриншоте
  в Android Studio есть кнопка камеры, или на реальном телефоне — кнопки
  громкость-вниз + питание)

## Шаг 7. Напиши Privacy Policy (обязательно для Google Play)

Google Play **не пропустит** приложение без ссылки на политику
конфиденциальности, если приложение работает с микрофоном и/или
отправляет данные на сервер (твоё — делает и то, и то).

В архиве есть черновик `docs/PRIVACY_POLICY_TEMPLATE.md` — открой его,
замени плейсхолдеры (`[ТВОЙ EMAIL]`, `[НАЗВАНИЕ ПРИЛОЖЕНИЯ]`) на свои
данные.

Дальше нужно разместить этот текст по публичному URL. Проще всего —
GitHub Pages (бесплатно):
1. Создай новый репозиторий на GitHub, например `musictabs-legal`.
2. Залей туда файл, назвав его `index.html` (переконвертируй markdown в
   простой HTML — можно просто обернуть текст в `<pre>` для скорости).
3. Settings → Pages → Source: "main branch" → Save.
4. Через пару минут политика будет доступна по адресу вида
   `https://твой-ник.github.io/musictabs-legal/`.

Сохрани этот адрес — он понадобится в Шаге 11.

## Шаг 8. Настрой AdMob (реклама для бесплатных пользователей)

1. Зайди на https://admob.google.com, войди тем же Google-аккаунтом,
   которым будешь регистрировать Play Console.
2. "Приложения" → "Добавить приложение" → "Нет, ещё не опубликовано в
   сторе" (пока у тебя нет опубликованного приложения — это нормально,
   AdMob позволяет создать заранее) → укажи "Android" → название
   "MusicTabs".
3. AdMob покажет твой **App ID** (формат `ca-app-pub-XXXXXXXXXX~YYYYYYYYYY`).
4. Открой `app/src/main/AndroidManifest.xml`, найди:
   ```xml
   <meta-data
       android:name="com.google.android.gms.ads.APPLICATION_ID"
       android:value="ca-app-pub-3940256099942544~3347511713" />
   ```
   Замени значение на свой App ID.
5. В AdMob создай рекламный блок: "Реклама" → "Создать блок объявлений"
   → тип "Баннер" → назови "musictabs_banner". Скопируй **Ad unit ID**
   (формат `ca-app-pub-XXXXXXXXXX/ZZZZZZZZZZ`).
6. Открой `app/src/main/java/com/musictabs/app/ads/BannerAd.kt`, замени:
   ```kotlin
   private const val TEST_BANNER_AD_UNIT_ID = "ca-app-pub-3940256099942544/6300978111"
   ```
   на свой реальный Ad Unit ID (и переименуй константу, если хочешь).

**Важно:** первые дни/недели после публикации AdMob может показывать
мало рекламы или "заглушки" — это нормально, ему нужно накопить
статистику. Не кликай сам на свои объявления даже "чтобы проверить" —
это нарушение политики AdMob, банят аккаунты без права восстановления.

## Шаг 9. Собери подписанный релизный файл (AAB)

Google Play принимает только формат `.aab` (Android App Bundle), не `.apk`.

1. В Android Studio: Build → Generate Signed Bundle / APK → выбери
   "Android App Bundle" → Next.
2. "Create new..." (создать новый ключ подписи, если делаешь это первый раз):
   - Key store path: выбери, где сохранить файл (например
     `musictabs-release-key.jks`) — **сохрани этот файл и пароли в
     надёжном месте, желательно в нескольких местах (облако + флешка).
     Если потеряешь его — не сможешь выпускать обновления приложения,
     придётся публиковать заново под новым именем пакета и терять всех
     пользователей.**
   - Заполни пароль, alias, ещё раз пароль, ФИО/организацию (можно
     свои данные), страну.
3. Next → выбери "release" → Finish.
4. Android Studio соберёт файл `app-release.aab` (путь покажется в
   уведомлении внизу, обычно `app/release/app-release.aab`).

## Шаг 10. Настрой подписку в Google Play Billing

Продукты подписки создаются **внутри** Play Console, поэтому сначала
нужно создать черновик приложения (следующий Шаг 11.1), а уже потом
вернуться сюда.

После того как приложение создано в Play Console:
1. Play Console → твоё приложение → "Монетизация" → "Продукты" →
   "Подписки" → "Создать подписку".
2. Product ID: введи ровно `musictabs_pro_monthly` (должно совпадать
   один-в-один с кодом — см. `billing/BillingManager.kt`, константа
   `PRO_SUBSCRIPTION_ID`). Если хочешь другое имя — поменяй и там, и там.
3. Укажи название ("MusicTabs Pro"), цену (например 199 ₽/мес — можно
   менять позже), период (месяц).
4. Сохрани и опубликуй подписку (кнопка "Активировать").

**Проверка перед реальными деньгами:** добавь себя как тестового
покупателя (Play Console → Настройка → Тестирование лицензий →
добавь свой email), тогда сможешь "покупать" подписку без реального
списания денег во время тестов.

## Шаг 11. Публикация в Google Play Console

### 11.1 Зарегистрируй аккаунт разработчика
1. Зайди на https://play.google.com/console/signup
2. Заплати $25 (разовый платёж, картой).
3. Заполни данные разработчика (для физлица — просто ФИО и адрес).

### 11.2 Создай приложение
1. Play Console → "Все приложения" → "Создать приложение".
2. Название: "MusicTabs" (или другое, если занято).
3. Язык по умолчанию, тип "Приложение", бесплатное/платное — выбери
   "Бесплатное" (монетизация через рекламу+подписку это позволяет).
4. Прими декларации внизу формы.

### 11.3 Заполни Store listing (карточка приложения)
Play Console → "Настройка магазина" → "Основная страница магазина":
- Краткое описание (до 80 символов): например "Тюнер и разбор аккордов
  для гитары, баса и укулеле"
- Полное описание (до 4000 символов): опиши функции подробно
- Иконка 512×512, feature graphic 1024×500, скриншоты — загрузи то,
  что подготовил в Шаге 5.

### 11.4 Заполни обязательные анкеты
Play Console → "Настройка приложения" (раздел слева), пройди все пункты
со значком "не заполнено":
- **Политика конфиденциальности** — вставь ссылку из Шага 7.
- **Рейтинг контента** — пройди опросник (для этого приложения обычно
  получится "Для всех" / "3+", вопросов про насилие/контент отвечай "Нет").
- **Целевая аудитория** — укажи 18+ или общую аудиторию (без контента
  для детей, раз в приложении есть покупки и реклама — так проще).
- **Реклама** — укажи "Да, приложение содержит рекламу" (это важно,
  Google проверяет соответствие).
- **Безопасность данных (Data Safety)** — обязательно укажи:
  - Собирается: аудио (микрофон) — используется только для функции
    тюнера, обрабатывается на устройстве, не передаётся на сервер;
  - Загружаемые пользователем аудиофайлы — передаются на твой сервер
    для анализа, не передаются третьим лицам (кроме случая, если ты
    используешь сторонний ML-сервис — тогда укажи это тоже);
  - Шифрование данных при передаче — "Да" (используешь HTTPS).

### 11.5 Обязательное закрытое тестирование (важно, новое правило Google)
С 2023 года Google требует от **новых** аккаунтов разработчиков пройти
закрытое тестирование, прежде чем открыть продакшен-доступ:
1. Play Console → "Тестирование" → "Закрытое тестирование" → создай
   трек, загрузи туда собранный `.aab` из Шага 9.
2. Добавь минимум **20 тестировщиков** (email-адреса друзей/знакомых,
   или используй сервисы вроде r/androidapps на Reddit, где люди
   помогают тестировать за отзыв).
3. Тестировщики должны присоединиться по ссылке-приглашению и
   **установить и открыть** приложение.
4. Тестирование должно идти **минимум 14 дней подряд** с активными
   тестировщиками.
5. Только после этого Play Console откроет кнопку перехода в продакшен.

Это не формальность "для галочки" — Google реально проверяет, что
тестировщики были активны. Планируй on минимум 2-3 недели на этот шаг.

### 11.6 Опубликуй в продакшен
После прохождения закрытого тестирования:
1. Play Console → "Продакшен" → "Создать новый релиз".
2. Загрузи финальный `.aab`.
3. Заполни "Release notes" (что нового — для первого релиза просто
   "Первый релиз MusicTabs").
4. Отправь на проверку. Ревью занимает от нескольких часов до 7 дней
   (обычно 1-3 дня для первого приложения).

## Шаг 12. После публикации

- **Мониторь крэши**: Play Console → "Качество" → "Android vitals" —
  проверяй раз в несколько дней первые недели.
- **Отвечай на отзывы** — это повышает доверие и рейтинг в поиске.
- **Обновления**: чтобы выпустить новую версию — повысь `versionCode`
  и `versionName` в `app/build.gradle.kts`, собери новый `.aab`
  (Шаг 9), загрузи в Play Console → Продакшен → Новый релиз. Закрытое
  тестирование для обновлений уже не обязательно (только для самого
  первого релиза с нуля).
- **ASO (App Store Optimization)** — подбирай ключевые слова в описании
  ("тюнер гитары", "аккорды песни", "разбор трека"), это сильно влияет
  на органические установки.

## Частые вопросы

**"Нужно ли мне юрлицо/ИП?"** — нет, для старта можно регистрировать
Play Console как физлицо. Для вывода денег с AdMob/Play Billing на
крупные суммы в некоторых странах может понадобиться подтверждение
налогового статуса — Google подскажет это в момент выплат.

**"Что если backend упадёт после публикации?"** — фича "Табы" перестанет
работать, но тюнер продолжит работать (он офлайн). Добавь мониторинг
(например бесплатный UptimeRobot) чтобы получать уведомление, если
сервер лёг.

**"Могу я взять деньги за скачивание вместо рекламы+подписки?"** — можно,
но фримиум (бесплатно + реклама + подписка) статистически даёт
на порядок больше суммарной выручки для новых небольших приложений,
чем платный вход — люди неохотно платят вперёд за неизвестное приложение.
