# MusicTabs — прототип

Приложение для музыкантов: тюнер (гитара/бас/укулеле) + разбор
загруженного трека на аккорды с таймингом. Есть монетизация:
баннерная реклама (AdMob) для бесплатных пользователей + подписка
"Pro" (Google Play Billing) с безлимитным разбором треков и без рекламы.

**👉 Если ты не программист или делаешь это впервые — начни с
[docs/PLAYSTORE_GUIDE.md](docs/PLAYSTORE_GUIDE.md).** Там пошагово
расписано всё: от установки Android Studio до публикации в Google Play.

## Backend — запуск

```bash
cd backend
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

Проверить:
```bash
curl -F "file=@test_progression.wav" http://localhost:8000/analyze
curl http://localhost:8000/analyze/<job_id>
```

Алгоритм (`chord_recognition.py`) уже протестирован на синтетической
прогрессии C–Am–F–G — таймкоды распознаются с точностью до ~0.05 сек,
аккорды все верны. На реальных записях (с шумами, реверберацией,
барабанами) точность будет ниже, особенно на:
- сложных джазовых аккордах (сейчас поддержаны только major/minor/dom7),
- полифонии с несколькими инструментами одновременно,
- очень тихих/грязных записях.

Следующие шаги для повышения качества (не реализовано в MVP):
- фильтрация низких частот перед chroma (бас часто "перетягивает" на себя),
- разделение источников (source separation, напр. Demucs/Spleeter) —
  выделить гитару/фортепиано перед анализом,
  добавить больше типов аккордов (sus, add9, dim, aug),
- HMM/Viterbi сглаживание вместо медианного фильтра (стандартный
  подход в академических chord recognition системах).

**Важно:** для реального продакшена нужно задеплоить backend на сервер
(например Render/Railway/свой VPS) и подставить его адрес в
`MainActivity.kt` (`BACKEND_BASE_URL`), плюс добавить очередь задач
(Celery/RQ + Redis) вместо in-memory словаря, т.к. сейчас при
перезапуске сервера все job'ы теряются, а при нескольких воркерах
in-memory JOBS не будет общим.

## Android — что уже реализовано

- **Тюнер** (`audio/YinPitchDetector.kt`, `audio/TunerEngine.kt`) —
  полностью рабочий алгоритм YIN, проверен на синтетических тонах
  (ошибка < 0.02 Hz). Слушает микрофон, определяет ближайшую струну
  выбранного инструмента и отклонение в центах.
- **Выбор инструмента** (`model/Instrument.kt`) — гитара/бас/укулеле
  со стандартными строями. Легко добавить кастомные строи (drop D и т.п.).
- **Экран тюнера** (`ui/screens/TunerScreen.kt`) — визуальный индикатор
  с цветом (зелёный/жёлтый/красный) и полосой отклонения.
- **Загрузка и анализ трека** (`network/`, `ui/screens/TrackAnalysisScreen.kt`) —
  выбор файла через системный picker → отправка на backend → поллинг
  статуса → отображение таймлайна аккордов.
- **Монетизация**:
  - `billing/BillingManager.kt` — подписка "Pro" через Google Play Billing
    (безлимитный разбор треков, без рекламы);
  - `billing/UsageLimiter.kt` — лимит 3 бесплатных разборов трека в месяц;
  - `ads/BannerAd.kt` — баннер AdMob для бесплатных пользователей;
  - `ui/screens/PaywallScreen.kt` — экран предложения подписки.
  - **Перед публикацией обязательно замени тестовые ID на реальные** —
    см. `docs/PLAYSTORE_GUIDE.md`, шаги 8 и 10.
- **Навигация** (`MainActivity.kt`) — Bottom navigation между Тюнером и Табами.

## Что нужно доделать (не входило в этот прототип)

1. **Отображение аккордов как аппликатур** — сейчас показываются только
   названия аккордов (`Am`, `F`...), а не грифовые диаграммы. Нужно
   добавить датасет аппликатур для каждого инструмента (гитара/бас/укулеле
   имеют разные пальцовки для одного и того же аккорда) и Compose-канвас
   для отрисовки грифа.
2. **Синхронное воспроизведение с подсветкой текущего аккорда** —
   ExoPlayer уже добавлен в зависимости, но плеер и синхронизацию с
   `chords` таймлайном нужно написать (слушать `currentPosition`,
   искать текущий сегмент, подсвечивать его в списке).
3. **Локальное сохранение разобранных треков** (Room DB), чтобы не
   гонять один и тот же файл на сервер повторно.
4. **Тесты на реальных записях** — синтетика доказывает корректность
   алгоритмов, но перед релизом обязательно нужно прогнать на реальных
   гитарных/басовых записях с разным качеством звука.
5. **CI сборка Android** — этот прототип не собирался реальным Gradle
   (в среде разработки нет Android SDK), поэтому перед первым запуском
   стоит открыть проект в Android Studio, дать Gradle sync и поправить
   мелкие несостыковки версий, если они возникнут.

## Дизайн решений и почему так

- **Тюнер работает офлайн, на устройстве.** Это единственно разумный
  вариант — задержка сети убила бы весь смысл тюнера.
- **Аккорды — на сервере.** Аккордовый анализ (chroma + матчинг с
  шаблонами) не тяжёлый по вычислениям, но зависит от librosa
  (тяжёлая нативная либа), которую неудобно тащить в APK. Сервер также
  даёт простор для апгрейда на более точные ML-модели в будущем без
  обновления приложения.
- **"Только аккорды", а не нота-в-ноту табулатура** — сознательное
  ограничение MVP: full instrument transcription (какая струна/лад)
  — открытая исследовательская задача, риск дать неверные табы выше
  пользы. Аккорды + ритм — это то, что реально работает и уже покрывает
  большинство случаев (аккомпанемент под песню).
